# Windows CPython attach experiments

These scripts preserve the external attach work on fresh Maya, 3ds Max, and Blender processes. They are reference experiments rather than a shipped flint connection mode. `probe.py` checks native injection and a host-thread callback without changing the scene. `bridge_spike.py` additionally loads the current exported Python Bridge, registers it with a temporary Rust backend, and creates and removes one scene object in Maya or 3ds Max. It starts and stops only the backend and host processes it creates.

Both scripts require a local Windows x64 host executable and an installed pydevd `pydevd_attach_to_process` directory containing `add_code_to_python_process.py`, `inject_dll_amd64.exe`, `attach_amd64.dll`, and `run_code_on_dllmain_amd64.dll`. The pydevd code and binaries remain external dependencies; this repository does not redistribute them. Use `--exe` for the host, `--injector` for that directory, and optionally `--out` for a new evidence directory. With no `--out`, the script creates a unique OS temporary directory. The Bridge spike also needs `--flint-exe` pointing to a built executable.

From this directory, run `python probe.py --host blender --exe <blender.exe> --injector <pydevd_attach_to_process> --blender-dispatch timer` to examine Blender's main-thread path. The default Blender mode uses `Py_AddPendingCall`. Run `python bridge_spike.py --host maya --exe <maya.exe> --injector <pydevd_attach_to_process> --flint-exe <flint.exe>` for an end-to-end Maya experiment; replace `maya` and its executable with `max` and `3dsmax.exe` for 3ds Max. Python 3.10 or newer is suitable for the controller; the target uses its own embedded interpreter.

`test_reference.py` keeps its process-launching checks opt-in. Set `FLINT_ATTACH_HOST`, `FLINT_ATTACH_EXE`, and `FLINT_ATTACH_INJECTOR` for the standalone probe; set `FLINT_ATTACH_SPIKE_HOST` and `FLINT_ATTACH_FLINT_EXE` as well for the Bridge roundtrip. `FLINT_ATTACH_STARTUP_WAIT` overrides the 60-second readiness delay, and `FLINT_ATTACH_BLENDER_DISPATCH=timer` selects the experimental Blender timer path. Run the test file with the locked Python test environment from `bridges/python`; no injection occurs when those host variables are unset.

The original local trials reached main-thread execution in Blender 5.2.2 with CPython 3.13.13, Maya 2024 with CPython 3.10.8, and 3ds Max 2024 with CPython 3.10.14. The Maya and Max probes used host-specific dispatch. The Blender pending-call path sometimes completed and sometimes produced no main-thread acknowledgement within 45 seconds. Registering a Blender timer from the injected worker completed one trial, but that registration has no established thread-safety guarantee. Injection helpers returned successfully even when the target code had not run, so both scripts require explicit file acknowledgements. These observations describe the original trials; the scripts are starting points for further experiments, not a compatibility claim.

The tracked adaptation has also been exercised with those three local host installations. Maya and 3ds Max completed Bridge registration and a Rust-backend scene roundtrip; Blender's timer mode returned a main-thread scene inspection. These checks run against fresh empty processes and preserve only locally generated evidence. The host-specific Bridge remains responsible for selecting the Qt binding already active in Maya or Max.
