# .NET platform

This platform supplies the managed binding and reusable execution capabilities. Export its sources and native core with `flint bridge export csharp`. For Unity installation and use, follow the [Unity guide](../../hosts/unity/README.md).

A host retains one [BridgeManager](src/Flint.Bridge/BridgeManager.cs), composed from its registration identity, runtime description, execution-capability factory, and initialization dispatcher. The factory runs when a Bridge is created and supplies an executor and a scheduler through [ExecutionCapabilities](src/Flint.Bridge/ExecutionCapabilities.cs); configuring or reusing a Bridge retains them. A Bridge that cannot be created disposes the scheduler it was given.

The native core orchestrates every execution: it prepares, runs, cancels, or discards it, combines output, and reports the result. An executor's Prepare turns a request into the value its Run executes; each returns a Task that may already be complete or finish later on any thread. A completed preparation runs without another scheduling round. A prepared value that is IDisposable is disposed after Run completes, or when the Bridge stops before running it. A failure is reported as `preparation_failed` or `execution_failed` with the exception text. Output writers stream to the core until their call completes; later writes are ignored. [CsharpSource](src/Flint.Bridge/CsharpSource.cs) creates C# method-body source, and [ManagedAssembly](src/Flint.Bridge/ManagedAssembly.cs) invokes a built assembly; hosts supply their compiler, log capture, and application-specific operations.

A scheduler posts each callback once to the thread where the host executes code and is disposed after its Bridge is released. The core posts from its own dispatcher thread, never the network thread, and prepares and runs code inside those callbacks. [ExecutionBinding](src/Flint.Bridge/ExecutionBinding.cs) only translates these calls, holding managed objects for the core until it releases them; it keeps no queue or stage of its own. [WorkerThread](src/Flint.Bridge/WorkerThread.cs) supplies a dedicated thread for hosts without an application loop, and [CallbackQueue](src/Flint.Bridge/CallbackQueue.cs) is drained by a host loop, as Unity does on Editor update. The callback contract lives in the [C ABI header](../../../crates/flint-bridge-core/include/flint_bridge_core.h).

Connect and Configure create a Bridge on the calling thread, so callers enter the thread required by the host. Attach uses the initialization dispatcher and one timeout budget for initialization and registration. When dispatch queues work onto an event loop, call Attach from a worker and keep the loop running. A timeout cancels initialization still queued; started initialization may complete after timeout. Connection settings, reconnection, status, and process ownership belong to [NativeCore](src/Flint.Bridge/NativeCore.cs).

Disconnect requests ordinary shutdown: the core cancels execution whose code has not started, while started preparation or execution finishes first. A false return requires retry after completion. Dispose instead ends the hosting context: it releases the Bridge even while host code runs, after which the core calls no more callbacks and late completions have no effect. It does not interrupt executing code. A created core keeps its native library loaded for the rest of the process. Hosts whose contexts unload call Dispose before their runtime stops accepting callbacks; Unity uses beforeAssemblyReload and quitting, with the domain-unload handler as a fallback.
